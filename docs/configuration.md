# Configuration and appearance

[Project overview](../README.md)

## Configuration sources

| Source                                                | Controls                                                                                       |
|-------------------------------------------------------|------------------------------------------------------------------------------------------------|
| [config/database.php](../config/database.php)         | MySQL connection from `DB_HOST`, `DB_PORT`, `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD`        |
| `protected/initial-settings.php` | Private initial values created by `app:setup`; used for fresh migrations and local reset |
| [config/initial-data.php](../config/initial-data.php) | Validates private initial settings and the initial blacklist before seeding |
| `app_settings` database table | Runtime legacy secret, HMAC key, password hash, base URL, timezone, admin username |
| [config/public-ui.php](../config/public-ui.php)       | Public wording defaults and private overrides                                                  |
| [config/templates.php](../config/templates.php)       | Twig settings and private template overrides                                                   |
| [config/translations.php](../config/translations.php) | Admin and public translation catalogues                                                        |
| [config/maintenance.php](../config/maintenance.php) | History retention, per-run limits, and maintenance lock path |
| [config/logger.php](../config/logger.php)             | Log destination, level, and file retention                                                     |
| [config/container.php](../config/container.php)       | Dependency injection bindings                                                                  |

Compose reads `.env` and maps `MYSQL_*` values to PHP's `DB_*` variables. PHP
outside Docker does **not** load `.env` automatically: supply environment variables
for both the web process and CLI using your hosting configuration.

Without overrides, `config/database.php` uses `127.0.0.1:3306`, database/user
`permits`, an empty password, and `utf8mb4`. Configure production credentials
explicitly. `APP_ENV=local` permits the local reset command; it does not enable
browser exception details.

## Runtime business settings

There is no settings editor in the admin panel. Update these rows through a
trusted database administration tool, using parameterized updates where scripted:

| `app_settings.setting_key` | Meaning                                                        |
|----------------------------|----------------------------------------------------------------|
| `signing_secret` | Original secret used for legacy verification and legacy reprints |
| `hmac_signing_key` | Independent 32-byte HMAC key, stored as 64 hexadecimal characters |
| `password_hash`            | Admin password hash generated by PHP `password_hash()`         |
| `admin_username`           | Admin login; initially `admin`                                 |
| `base_url`                 | Public URL prefix used when issuing QR links                   |
| `timezone`                 | Expiration and admin display timezone; initially `Europe/Riga` |

Changing the admin username or password hash invalidates existing admin sessions
and does not alter permit signatures. Changing `signing_secret` invalidates legacy
signatures; changing `hmac_signing_key` invalidates version 2 signatures. Back up
both values. Overlapping-key rotation is not implemented. Updating `base_url`
affects newly generated links; it does
not rewrite printed QR codes. Dates are interpreted in the configured timezone.

`app:setup` generates an independent HMAC key as 64 hex characters and stores it
in the private initial settings file, or accepts an existing key through a hidden
prompt. The initial migration copies that key into `app_settings`. The
stored value is reused on later requests and migration reruns; it is not generated
per request. Initial values do not rotate a key already stored in the database.
See [signature compatibility](database.md#signature-versions).

## Public wording

The public verification pages and printed permits use the `public` translation
domain with a fixed Latvian locale, independently of the admin language. Shared
messages live in [translations/public.lv.php](../translations/public.lv.php).
The neutral landing page also uses this catalogue; its default title and heading
are English and can be overridden.

Keep deployment-specific wording private:

```sh
mkdir -p protected
cp config/public-ui.example.php protected/public-ui.php
```

Edit the returned PHP array. Both sections are optional string maps:

```php
<?php

return [
    'parameters' => [
        '%location%' => 'autostāvvietas teritorijā',
        '%check_location%' => 'autostāvvietas teritorijā',
        '%guest_location%' => 'autostāvvietas teritorijā',
        '%basis%' => 'apstiprinātajiem noteikumiem',
    ],
    'messages' => [
        'check.title' => 'Atļaujas pārbaude',
    ],
];
```

Use `parameters` for repeated wording and `messages` to replace complete messages
from the catalogue. Separate check and print locations allow different punctuation.
Keep dynamic placeholders such as `%id%`, `%apartment%`, `%term%`, and `%vehicle%`
where required. Missing entries use shared defaults. Values render as escaped
text, not HTML or Twig.

`PUBLIC_UI_CONFIG` selects another PHP file; relative paths start at the project
root and absolute paths are supported. A missing default `protected/public-ui.php`
is allowed. An explicitly configured missing file causes an error.

To reproduce an existing deployment, upload its exact private messages and
parameters separately from the source release, then compare resident, guest,
valid, invalid, and landing pages. These display settings do not affect signatures
or database seeds and survive a database reset.

## Templates and assets

Shared templates are in [templates/](../templates). Twig enables HTML escaping
and strict variables, disables debugging, and enables compilation caching outside
local/test environments. `Renderer::render()` resolves names such as `valid` to
`valid.html.twig`.

Private overrides in `protected/templates/` take precedence over shared template
names. Set `PUBLIC_TEMPLATE_DIRECTORY` to use another directory. A missing override
directory simply leaves the shared templates active.
For production cache paths, warmup, and invalidation after private template changes,
see [production configuration](performance.md#twig-compilation-cache).

| Private override                       | Purpose                                              |
|----------------------------------------|------------------------------------------------------|
| `public-check.css.twig`                | CSS included after shared public verification styles |
| `permit.css.twig`                      | CSS included after shared printed permit styles      |
| `valid.html.twig`, `invalid.html.twig` | Complete verification markup                         |
| `permit.html.twig`                     | Complete printed permit markup                       |
| `home.html.twig`                       | Complete landing page markup                         |

CSS fragments contain CSS without `<style>` tags. Private Twig files are trusted
templates and can execute Twig expressions. For failure messages, use
`{{ public_reason(reason) }}`; `reason` is an enum, not translated text.
`make lint-templates` checks shared templates and active private overrides.

Permit templates receive `qrimage` (a locally generated SVG data URI) and `qrtext`
(the exact signed URL). Use `<img class="qr" src="{{ qrimage }}" alt="{{ qrtext }}">`
in private permit overrides to keep generation local. Older overrides referencing
an external QR service must be updated separately.

Verification and printable templates receive `cspNonce`, a fresh nonce matching
the response's Content Security Policy. Shared templates already attach it to the
CSS fragment wrapper, so fragment files need no changes. Complete overrides must
use `<style nonce="{{ cspNonce }}">` for inline CSS and
`<script nonce="{{ cspNonce }}">` for trusted inline JavaScript, or use local
external files. Inline event handlers, external hosts, embedded frames, and remote
fonts are blocked. Replace old CDN/font links with the local URLs from the shared
templates. A complete override needs review before deployment; the application
does not modify private templates automatically.

Shared public assets retain their URLs:

- `/permit/check.css`: verification layout and status styles.
- `/permit/style.css`: permit layout and print rules, including hidden admin controls when printing.
- `/permit/assets/icons/`: local valid/invalid SVG graphics.
- `/permit/assets/fonts/stylesheet.css`: local plate font using WOFF2 with WOFF fallback.

Their source files are under `public/permit/`. Reviewed third-party files and
licenses are under `public/vendor/`; application CSS and JavaScript are under
`public/assets/`. The added font stylesheet is `/vendor/fonts/fonts.css`. Only `public/` is the document root.
For fixed `public_html` deployments, the entry point accepts an optional absolute
`APP_ROOT` environment value selecting the private application directory; it
defaults to the parent of the entry point's directory. Other private override
paths still resolve relative to the application configuration directory, not the
web root. See [deployment layouts](deployment.md#deployment-layouts).

Default private config, templates, logs, and cache paths under `protected/` are
ignored by Git and outside the public document root. Keep custom private paths
outside `public/` too. See [deployment](deployment.md) for caching and release checks.

## Admin translations

UTF-8 PHP arrays in `translations/admin.en.php`, `translations/admin.lv.php`, and
`translations/admin.ru.php` are loaded by Symfony Translation. Keep keys and
`%placeholder%` names consistent; tests check catalogue consistency.

The language selector uses an allowlisted `lang` query value (`en`, `lv`, `ru`),
then the saved `admin_language` cookie, then English. English is also the fallback
for missing translations. The preference lasts one year and is scoped to `/admin`.
Switching languages preserves URL filters and pagination, but not unsaved form
input. It does not change public verification or printed permit wording.
